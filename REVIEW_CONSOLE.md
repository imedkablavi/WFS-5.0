# Review Console

WFS Recovery Toolkit 0.7 adds a browser-based review and storage-management layer for recovered video.

The design borrows workflow ideas common in professional forensic video tools: preserve the source, separate recovery from review, keep technical reports and hashes, allow batch triage, and record operator actions. The implementation remains Linux-first and lightweight.

## Start in read-only review mode

```bash
python3 wfs_recover.py review \
  --root /path/to/recovered \
  --bind 0.0.0.0 \
  --port 8090
```

The command prints a token-protected URL. Open that exact URL in the browser.

Read-only review mode lets you:

- preview recovered MP4 video with seek support
- filter by `PASS`, `REVIEW`, `FAIL`, filename, time, and reasons
- sort by time, size, or QC status
- mark videos as `KEEP`, `REVIEW`, or `DISCARD`
- add notes
- select multiple videos at once
- view recovered-video total size and filesystem free space
- export review decisions as CSV

## Enable deletion

Deletion is intentionally disabled by default.

```bash
python3 wfs_recover.py review \
  --root /path/to/recovered \
  --bind 0.0.0.0 \
  --port 8090 \
  --allow-delete
```

When enabled, the dashboard can permanently remove recovered video files from the output `video/` directory so space is actually returned to the destination filesystem.

The recovery source, RAW image, WFS device, manifest, logs, and thumbnails are outside the deletion scope.

### Safety rules

- paths are resolved and checked against the recovery `video/` directory
- `..`, absolute paths, symlinks, and unsupported file types are rejected
- files marked `KEEP` are protected from normal deletion
- bulk delete refuses a selection containing `KEEP` files
- every delete requires a browser confirmation
- file size is checked again immediately before deletion to detect stale browser state
- a random session token protects API requests
- all decisions and deletes are written to `review_audit.jsonl`
- deleted files remain represented in `review_state.json` and review CSV even after their bytes are removed
- original manifest entries and hashes are preserved

## Optional quarantine

Instead of permanent deletion:

```bash
python3 wfs_recover.py review \
  --root /path/to/recovered \
  --allow-delete \
  --quarantine-dir /different/filesystem/wfs-trash
```

This moves removed files to a quarantine directory. To free space on the recovery USB/disk, quarantine must be on a **different filesystem**. The server warns if quarantine appears to be on the same filesystem.

## Files created by review

```text
recovered/
├── manifest.json
├── manifest.csv
├── index.html
├── review_state.json
├── review_audit.jsonl
├── video/
└── ...
```

`review_state.json` tracks operator decisions. `review_audit.jsonl` is append-only in normal use and records timestamps, action type, file path, size/hash when available, and client address.

## Relationship to the recovery report

`index.html` generated by recovery remains a static forensic/QC report.

The `review` command is a local application server because a static HTML file cannot safely delete files from the filesystem. This separation is deliberate: static reports remain portable, while destructive operations require an explicitly started, token-protected local service.

## Professional workflow inspirations

The project does not copy proprietary software, but it follows useful workflow patterns visible in established forensic video products:

- Magnet Witness emphasizes direct CCTV/DVR acquisition, review progress, centralized media review, deleted/partially overwritten video recovery, and auditable reports.
- Amped DVRConv emphasizes preserving originals, producing compatible review files, batch processing, quality-preserving conversion, hashes, and detailed conversion reports.

WFS Recovery Toolkit applies similar principles to an open Linux recovery workflow: immutable source handling, neutral candidate naming, explicit QC states, operator review states, preserved hashes/manifests, batch triage, and an audit trail for destructive cleanup.

## Security note

Binding to `0.0.0.0` makes the review console reachable on the local network. The token is required, but the service is HTTP rather than HTTPS. Use it only on a trusted LAN/VPN, or bind to `127.0.0.1` and use an SSH tunnel for higher-security environments.
